# Language gaps — 1.0.10-beta

The compiler is frozen for every **library** front. Every library front is built from plain botopink
plus `@Decl`, comptime, `@emit` and `#[@external]`, and a library front that needs a compiler change
does not get one. What it does instead is write the nearest form that parses today, mark the line
`// LANGUAGE GAP:`, and record the gap here.

What is new in this milestone is that the compiler is **not** frozen for
[`00-compiler-carry-over`](./00-compiler-carry-over/README.md), which carries the open compiler fronts
of 1.0.5-beta (`01-checker`, `13-module-identity`, `15-language-surface`, `16-formatter`,
`17-beam-memory`, …). The last column of every table below says which of those fronts a gap belongs
to, or `—` when it belongs to none and stays a library-side workaround. A gap owned by `00` is
**still worked around** by the library front that hits it — `00` runs beside the libraries, not ahead
of them, except for the two items pulled ahead in [`fronts.md`](./fronts.md) (module identity and
`@src()`).

This file is the feed for the next milestone. The exit gate in [`fronts.md`](./fronts.md) requires
every `// LANGUAGE GAP:` marker left in an example to appear in a spec here — a gap that exists only
as a comment in a `.bp` file is a gap nobody will fix.

> Carried from `specs/1.0.9-beta/language-gaps.md` on 2026-09-20; every 1.0.9 row is unchanged in its
> first four columns. Added: the *1.0.10 owner* column, the *Compiler-front gaps* table (rows that are
> 1.0.5-beta compiler fronts and were not yet written as library gaps), the `@src()` row owned by
> [`01-std/src-builtin.md`](./01-std/src-builtin.md), and the three packaging rows in *Toolchain gaps*.

Rows are added as fronts are written. A row names the gap, where it bites, what the nearest valid
form is today, and what surface would close it.
