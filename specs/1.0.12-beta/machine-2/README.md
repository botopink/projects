# Machine 2 — the work queue (the maintainer, 2026-10-17, night)

What machine 2 (backends, runtimes, std, tooling, the gate; front 164 wasm-gc) executes without a maintainer
decision, in order. Every item is fixed by a decision in [`decisions-taken.md`](../decisions-taken.md) or by a
step's README; what still waits on the maintainer is listed at the end and is **not** opened. The sister queue is
[`../machine-1/README.md`](../machine-1/README.md).

**Rules for the night**

1. The builtins group comes first (144 README § Machines rule 9), in the order decision 605 fixed:
   **B-136 → 165 s10 → B-139 → B-140**. Rule 9's "no other new step opens" is relaxed by the maintainer for
   the items of § After the group below, under one condition: an item runs only when its files are disjoint
   from the group's open threads (`libs/std/**`, the builtins, `compiler.bp`, the backends' `Implementation`
   readers, `decorator_*` / `template_*` / `comptime_*` cells). An item that would touch them waits.
2. The hold: nothing lands on botopink-lang's `feat` from here until machine 1 posts B-136's hash — the
   branches `front/b138p`, `front/b138d` and B-143's are ready and land right after it, in that order, each
   rebased and its checks re-run. Work on the items below goes on in worktrees meanwhile.
3. Every thread: "Read `scripts/thread-rules.md` first" (484); commits with `--no-verify` are the group's
   exception only (rule 9); every heavy command through `scripts/gate.sh exec`; the four-line report.
4. A thread that meets a choice no decision fixes stops and files the question in `decisions-pending.md`
   (English, then the Portuguese page), and the coordinator moves to the next item — never a guess.
5. The coordinator records each landing in `status.md` and the step's README in the same push; the
   `decisions-taken.md` of each repository is regenerated by `scripts/decisions-split.py` (482).
