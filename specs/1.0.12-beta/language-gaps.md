# Language gaps — 1.0.12-beta

The compiler is frozen for every **library** front: a library is plain botopink plus `@Decl`,
comptime, `@emit` and `#[@External.<Target>]`. A library front that needs a compiler change writes
the nearest form that parses today, marks the line `// LANGUAGE GAP:` and records the gap here. The
compiler is not frozen for [`01-compiler`](./01-compiler/README.md); a gap owned by a compiler front
is still worked around by the library front that hits it — the compiler runs beside the libraries,
not ahead of them.

**Exit gate** (`fronts.md`): every `// LANGUAGE GAP:` marker in a library or a front's `examples/`
names a row here. A row gated on a maintainer question names it (`lg2-a…w`, `std-e`; all in
[`decisions-pending.md`](./decisions-pending.md) § Open); until it is answered the row opens no
front and the nearest form is the design (the most restrictive reading). A gap closes in this order:
its markers go, then their index rows, then the gap row.

Row ids (`T<n>`, `C-<n>`, `row <n>`) are the names the `01-compiler` fronts use for a row.

## Marker index

Checked on every push by `scripts/language-gap-markers.sh` (`hook-integrity`, check 5). A marker is
the literal `// LANGUAGE GAP` in a tracked `.bp` file of any repository under `repository/`, or of
this repository outside the closed milestones' spec trees. One row per file holding a marker: its
path from the meta root, its marker count, and the gap rows those markers name, spelled as the
tables spell the bold title. The script fails on a file with a marker and no row, a count that
differs, a named gap row gone from the tables, and a row naming a file with no marker. No flag
exempts a file.
