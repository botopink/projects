## Method
- Slug rule (`tests/helpers.zig:63-76`): take the test name after the **first** `": "`, lowercase it, keep ASCII alphanumerics, and collapse every other run of characters into one `_`. I recomputed the slug for every test with a script (`scratchpad/run-comptime-errors/slugs.py`).
- `assertTypeErrorSnap` writes `comptime/{node,erlang}/errors/<slug>`. `assertComptimeAstSingle` writes `comptime/{node,erlang,wasm,beam}/<slug>`. `assertInfersOk` writes no snapshot.
- Every error snapshot (72) and AST snapshot (4) exists. Each `node` copy is byte-identical to its `erlang` copy (error snapshots) or to its `erlang`/`beam`/`wasm` copies (AST snapshots). Checked with `filecmp`.
- Orphans: none. All 106 files in `snapshots/comptime/node/errors/` and every `snapshots/comptime/node/*.snap.md` map to a test name somewhere in `src/`.
- I read all 76 snapshots in full and cross-checked them against `comptime/infer.zig`, `comptime/diagnostics.zig`, `lexer.zig` and `parser*.zig`.
- Corroborating probes used the prebuilt `zig-out/bin/botopink check` (mtime 2026-09-14 11:23) on scratch projects. **Caveat:** that binary is older than the latest `infer.zig` commit (173f31d, 2026-09-15). Every probe claim below is also backed by source code.

## Cross-cutting findings (root causes behind several rows)
1. **The AST harness does not fail on a parse or type error.** `snapshot.zig:640-642` renders `.validationError`, `.typeError` and `.parseError` as the SOURCE section only, and `helpers.zig:assertComptimeAst` never checks the outcome. A broken "success" test therefore snapshots cleanly. `nested_pattern_matching` is exactly this case. Out of batch, `snapshots/comptime/node/non_empty_list_pattern.snap.md` also has no `TYPED AST JSON` section and also uses `default`.
2. **Return values are never unified with the declared return type.** `infer.zig:2867-2870`:
   ```
   // Infer body (for type checking; we ignore the result for now).
   for (f.body) |stmt| {
       _ = try inferExpr(env, stmt.expr);
   }
   ```
   and the `.@"return"` jump arm (`infer.zig:5458-5555`) never unifies `valPtr` with the fn return type. A probe confirms that `fn f() -> string { return 1; }` checks OK. Every `assertInfersOk` "happy path" that relies on `return v` to pin a type verifies nothing.
3. **Logical operators unify operand-first.** `infer.zig:5371-5374` and `5410-5411` call `unifyAt(env, operandTy, bool, loc)`, but `unifyAt` is documented as "always called target-first (`unifyAt(param, arg)`)" (`infer.zig:3768-3769`). As a result, "expected" and "found" are swapped in the rendered error.
4. **Effect/external diagnostics point at the body, not the declaration.** `infer.zig:2789` (`const fnLoc = if (f.body.len > 0) f.body[0].expr.getLoc() else null`) and `infer.zig:2073` do this. Wrapper errors land on the first body statement, and `declare fn` errors have no location at all.
5. **Many `TypeError` constructors carry no location.** Examples: `missingMethod`, `unknownMethod`, `unknownInterface`, `ambiguousMethod` (`infer.zig:330-385`); `extendRequiresInterface`, `redundantActivation`, `notAnExtension` (`infer.zig:761-783`); pub-default (`infer.zig:190-196`); RG3 (`infer.zig:4638-4642`); `add`/`sub`/`mul` use `unify` without `At` (`infer.zig:5383-5395`). These snapshots have no `┌─` box, so a regression that moves the error would not be visible.
6. **Renderer cosmetics (`helpers.zig:213,221`).** The gutter `"  │"` has a fixed width, so it misaligns for line numbers of 10 or more (`19 │ val r = …` over `  │`). It also joins constraint lists with `", "` (`helpers.zig:370-373`), which renders `type string, int, bool` instead of the source `string | int | bool`.
