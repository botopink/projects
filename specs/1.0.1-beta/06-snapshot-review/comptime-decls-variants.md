## Cross-cutting findings (root causes behind many rows)

| # | Finding | Evidence |
|---|---|---|
| X1 | **Success snapshots silently record failed compiles.** `buildSnapshot` writes nothing for failed outcomes, so a test whose source fails to parse or type-check still "passes" and its snapshot holds only `SOURCE CODE`. 10 tests in this batch are in that state (see the rows marked *source-only*). | `modules/compiler-core/src/comptime/snapshot.zig:640-642`: `.validationError => {},` / `.typeError => {},` / `.parseError => {},` |
| X2 | **`fn_def` JSON is not inferred data.** Param and return types are read back from the syntax (`typeNameFromTypeRef`). Any typeRef that is not `.named` prints as `"?"`, and `body` holds raw source lines. Fn-centric tests therefore never show inferred types. | `snapshot.zig:235-239`: `.named => ... else => "?",`; `snapshot.zig:417,428`: `.type = typeNameFromTypeRef(p.typeRef)` / `typeNameFromTypeRef(rt) else "void"` |
| X3 | **Return statements are never unified with the declared return type.** Because of this, fn/lambda tests with a declared `-> T` do not check what the body returns. | `INF:2868-2871`: `// Infer body (for type checking; we ignore the result for now).` / `_ = try inferExpr(env, stmt.expr);`. `INF:5561`: a return is typed `void`, with no unify. (CLI) `fn g() -> string { return 1; }` → `Checked`. |
| X4 | **A `case` expression's type is always a fresh type variable**, and the arms are never unified with each other. | `INF:7468`: `return TypedExpr{ .collection = .{ .loc = loc, .type_ = try env.freshVar(), .kind = .{ .case = ...`. (CLI) `val a: bool = case 42 { 0 -> "a"; _ -> "b"; };` → `Checked` |
| X5 | **A method with no return annotation gets a fresh-var return type, and unknown methods fall through to a permissive path.** As a result, `x.m()` type-checks even when no method `m` exists. | `INF:1002-1006`: `Only methods with an explicit return-type annotation get a stored signature ... leave such calls to the fresh-var fallback`. `INF:6490`: `unknown methods fall through to the permissive path`. (CLI) `record Pato { id: i32 } val donald = Pato(1); val splash = donald.swim();` → `Checked`. |
| X6 | **Record-update spread (`..x`) is a positional hack.** With one spread and fewer than two other args, the spread unifies positionally against field 0. Otherwise the remaining args unify positionally and **labels are ignored**. | `INF:7201`: `// Keep the historical spread behavior (and snapshots) for narrow update/error cases.`; `INF:7220-7230` (line 7228) unifies `f.params[paramIndex]` without looking at the label. (CLI) `Person(..alice, name: "Bob", nickname: 25)` → `Checked`; `Person(..alice, age: 25)` → `'Person' expects 3 argument(s), got 2`. |
| X7 | **The comptime folder only folds integers.** Every `binaryOp` is folded with `evalConstInt`, so float and string operands become `0`. | `modules/compiler-core/src/comptime/eval.zig:85-96`: `.binaryOp => ... return .{ .integer = switch (b.op) { .add => lhs + rhs,`; `eval.zig:188`: `.numberLit => |n| std.fmt.parseInt(i64, n, 10) catch 0, else => 0` |
| X8 | **`"id"` on `record_def` / `enum_def` looks like a placeholder: it is `0` in every snapshot.** Two distinct records in one module both get `0` (outside this batch: `SN/disjoint_records_merge_correctly.snap.md` has `"name": "User", "id": 0` and `"name": "Timestamps", "id": 0`). The serializer defaults to 0 when the lookup misses (`snapshot.zig:442`: `.id = resolvedTypeId orelse 0`). Root cause not isolated. | every `record_def`/`enum_def` in this batch shows `"id": 0` |
| X9 | **Interfaces, `implement` blocks, record/enum methods, enum variants and doc comments never reach the JSON.** | `snapshot.zig:458-465`: `interface_def` has only name/generic. `record_def` holds only `fields`. `implement` produces no binding. |
| X10 | **Record method bodies are best-effort and skipped on inference gaps.** | `INF:2911` (doc comment of `inferTypeMethods`): `This is BEST-EFFORT: a method whose body trips an inference gap is skipped`. (CLI) a method body `return self.nope;` → `Checked` |
