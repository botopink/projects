2. **Key harness fact**: `snapshot.buildSnapshot` (snapshot.zig:540-645) only emits `TYPED AST JSON` for `.ok`; `.parseError`/`.typeError`/`.validationError` produce a SOURCE-only snapshot (snapshot.zig:642-644, three empty arms), and `h.assertComptimeAst` never checks the outcome. A success snapshot with no `TYPED AST JSON` section therefore **proves the test compiled with an error while still passing**. (templates.zig:383-385 documents this exact hazard: "snapshot-only assertions accept error outcomes as a SOURCE-only snapshot, which silently hides template-evaluation failures".)

Probes: `zig-out/bin/botopink check` (rebuilt from HEAD `96ff203` on 2026-09-15 19:48) run on the test sources and small variants inside scratch projects under `scratchpad/rev-ct-templates-generics/` (no repo writes; no `zig build`). ## Cross-cutting compiler findings (evidence for several verdicts)

- **G1 — `return` values are never unified with the fn's declared return type.** *(confirmed)* HEAD `src/comptime/infer.zig:5561`: `return TypedExpr{ .jump = .{ .loc = loc, .type_ = try env.namedType("void"), .kind = .{ .@"return" = valPtr } } };` (value inferred, no unify); `inferFnDecl` at infer.zig:2868: `// Infer body (for type checking; we ignore the result for now).` Probe: `fn p() -> string { val r: i32 = 1; return r; }` → `Checked`. Any test whose only assertion is "a `return` matches the annotation" cannot fail.
- **G2 — case pattern payload bindings are not typed from the variant field type.** *(confirmed)* Probes (all `Checked`): `enum E { A(v: i32), B } … case e { A(v) -> f(v); … }` with `fn f(s: string)`; `Dog(b) | Cat(b) -> f(b)` with `breed: string` and `f(x: i32)`; `Circle(radius) -> f(radius)` with `radius: f64`, `f(s: string)`; guard binding `x if (x > 0) -> f(x)` with `n: i32`, `f(s: string)`. Control: `A(v) -> f(1)` does red (`expected string, got i32 at main:4:30`).
- **G3 — record method bodies are best-effort; their type errors are swallowed.** *(confirmed)* infer.zig:2911: "This is BEST-EFFORT: a method whose body trips an inference gap is skipped". Probe: `record Fetcher { url: string, #[@result] fn load(self: Self) -> @Result<string, string> { throw 5; } }` → `Checked`, while the same body as a top-level fn reds `expected string, got i32`.
- **G4 — snapshot renderer is lossy** *(confirmed)* (snapshot.zig): `typeNameFromTypeRef` (snapshot.zig:236-241) returns `"?"` for every non-`.named` TypeRef (optional, `@Result<…>`, `@Future<…>`, anonymous record), `typeNameOf(.func)` returns only the return type (snapshot.zig:508 `.func => |f| return typeNameOf(allocator, f.ret)`), `"?"` is also printed for unbound type vars (snapshot.zig:509 `.typeVar => return allocator.dupe(u8, "?")`), fn bodies render only the first source line of each statement, and `"id"` is `0` for all 53 record/enum defs in `snapshots/comptime/node` (`grep '"id": '` → only `"id": 0`; the `.id = resolvedTypeId orelse 0` fallbacks are snapshot.zig:443 and :454). Effect annotations (`#[@result]` etc.) and narrowed types are never rendered — a scan of every `TYPED AST JSON` section finds no effect key at all. So even `.ok` snapshots in this batch cannot show narrowing, effects or fn types.
- **G5 — top-level expression statements (`@print(...)`) are a parse error.** *(confirmed)* Probe: `fn f() -> i32 { return 1; }\n@print(f());` → `error: parse error in main`. Root cause of most SOURCE-only snapshots here.
- **G6 (new, 2026-09-15) — a leading-dot enum literal in a decorator body breaks the decorator module.** A body containing `if (decl.kind != .Record)` compiles the generated Erlang with an unbound variable: `error: the decorator module did not compile: … [{{5,36},erl_lint,{unbound_var,'Record'}}]`. The fully-qualified form (`DeclKind.Record`) works (`Checked in ~383 ms`). Both `decorators.zig:155` and `decorators.zig:170` use the dot form and pass only because `assertInfersOk` never runs the body (infer.zig:2293 `const ctx = env.templateEval orelse return;`).
