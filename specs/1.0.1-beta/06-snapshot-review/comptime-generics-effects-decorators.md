## Method / evidence sources and caveats

1. Read `src/comptime/tests/helpers.zig`, `src/comptime/snapshot.zig`, `src/comptime/AGENTS.md`, every test file in the batch, and every snapshot they write (node copy).
2. **Key harness fact**: `snapshot.buildSnapshot` (snapshot.zig:549-643) only emits `TYPED AST JSON` for `.ok`; `.parseError`/`.typeError`/`.validationError` produce a SOURCE-only snapshot, and `h.assertComptimeAst` never checks the outcome. A success snapshot with no `TYPED AST JSON` section therefore **proves the test compiled with an error while still passing**. (templates.zig:382-384 documents this exact hazard: "snapshot-only assertions accept error outcomes as a SOURCE-only snapshot, which silently hides template-evaluation failures".)
3. Probes: `zig-out/bin/botopink check` run on the test sources (and small variants) inside scratch projects under `scratchpad/run-comptime-generics/` (no repo writes; no zig build). **Caveat**: the binary was built 2026-09-14 11:23 (≈ `731963d`). Since then `infer.zig` changed only in decorator/template/`interfaceLit` code (`git diff 731963d HEAD -- src/comptime/infer.zig` hunks at 2241-2411, 3316-3665, 7165-7174, 7492), and `parser/exprs.zig` gained the `@Iface(field: …)` literal plus an optional `;` before `}` in block exprs (exprs.zig:163). ## Cross-cutting compiler findings (evidence for several verdicts)

- **G1 — `return` values are never unified with the fn's declared return type.** HEAD `src/comptime/infer.zig:5561`: `return TypedExpr{ .jump = .{ .loc = loc, .type_ = try env.namedType("void"), .kind = .{ .@"return" = valPtr } } };` (value inferred, no unify); `inferFnDecl` ~2866: `// Infer body (for type checking; we ignore the result for now).` Probe: `fn p() -> string { val r: i32 = 1; return r; }` → `Checked`. Any test whose only assertion is "a `return` matches the annotation" cannot fail.
- **G2 — case pattern payload bindings are not typed from the variant field type.** Probes (all `Checked`): `enum E { A(v: i32), B } … val r = case e { A(v) -> f(v); … }` with `fn f(s: string)`; `Dog(b) | Cat(b) -> f(b)` with `breed: string` and `f(x: i32)`; `Circle(radius) -> f(radius)` with `radius: f64`, `f(s: string)`; guard binding `x if (x > 0) -> f(x)` with `n: i32`, `f(s: string)`. Control: `A(v) -> f(1)` does red (`expected string, got i32 at main:5:19`).
- **G3 — record method bodies are best-effort; their type errors are swallowed.** infer.zig ~2908: "This is BEST-EFFORT: a method whose body trips an inference gap is skipped". Probe: `record Fetcher { url: string, #[@result] fn load(self: Self) -> @Result<string, string> { throw 5; } }` → `Checked`, while the same body as a top-level fn reds `expected string, got i32 at main:3:5`.
- **G4 — snapshot renderer is lossy** (snapshot.zig): `typeNameFromTypeRef` returns `"?"` for every non-`.named` TypeRef (optional, `@Result<…>`, `@Future<…>`, anonymous record), `typeNameOf(.func)` returns only the return type (snapshot.zig:507 `.func => |f| return typeNameOf(allocator, f.ret)`), `"?"` is also printed for unbound type vars (snapshot.zig:508), fn bodies render only the first source line of each statement, and `"id"` is `0` for all 53 record/enum defs in `snapshots/comptime/node` (`grep '"id": ' | uniq -c` → only `"id": 0`). Effect annotations (`#[@result]` etc.) and narrowed types are never rendered. So even `.ok` snapshots in this batch cannot show narrowing, effects or fn types.
- **G5 — top-level expression statements (`@print(...)`) are a parse error.** Probe: `fn f() -> i32 { return 1; }\n@print(f());` → `error: parse error in main`. Root cause of most SOURCE-only snapshots here.
