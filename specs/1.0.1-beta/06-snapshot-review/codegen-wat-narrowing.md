# Snapshot review: codegen `wat.zig` + `narrowing.zig`

- **Batch:** `modules/compiler-core/src/codegen/tests/wat.zig` (34 tests), `modules/compiler-core/src/codegen/tests/narrowing.zig` (11 tests)
- **Tests reviewed:** 45
- **Snapshots reviewed:** 180 (45 slugs x 4 backends). 148 have content. **32 are 0-byte files** (8 slugs x 4 backends).
- **Slug rule:** `helpers.slugFromSrc`. It drops the `wat: ` / `js: ` prefix (everything up to the first `": "`), then `slugify` lowercases and folds runs of non-alphanumerics into `_`. For example `js: narrow ---- if null check with print` becomes `narrow_if_null_check_with_print`. All tests use `h.assertJsSingle`, so all 4 backends are generated.
- **Path prefix used below:** `SN = modules/compiler-core/snapshots/codegen`
- **Name, test and snapshot checks:**
  - For every non-empty snapshot, the SOURCE CODE section matches the test body byte-for-byte (checked by script).
  - No snapshot is missing.
  - There are no orphans: every `SN/<target>/<slug>.snap.md` maps to a test in `src/codegen/tests/*.zig`.
  - Three narrowing slugs also exist under `snapshots/comptime/*`, produced by `src/comptime/tests/narrowing.zig` (`infer: narrow ---- …`). They live in a different directory, so they don't collide.
- **How verified:**
  - Every non-empty JS, `.erl`, `.S` and `.wat` was copied into `scratchpad/run-wat-narrowing/` and run there with `node`, `erlc`+`erl`, `erlc +from_asm`+`erl` and `wasmtime 45.0.0`.
  - Library-style fixtures (no `main`) were checked by adding exports and calling the functions directly.
  - The 0-byte-snapshot sources were run through `zig-out/bin/botopink check` in a scratch project (re-run on the re-check with a binary built at HEAD, see below).

## Cross-cutting observations (not counted as separate verdicts)

1. **WAT `$__print_i32` prints multi-digit negatives wrong.** It is shared by every WAT snapshot with `@print`. The sign fix-up calls `$__memmove` with `dst = buf+len` instead of `buf+1`: `local.get $buf` / `local.get $len` / `i32.add` / `local.get $buf` / `local.get $len` / `call $__memmove` (e.g. `SN/wasm/tuple_construct_then_destructure.snap.md`). Verified: `-12` prints as `-21` and `-123` as `-231`. `-1` prints fine, which is why `try_catch_returns_handler_value_on_error` doesn't catch it. **Re-check:** confirmed — the helper is emitted from `wat.zig:333-338` and is present in 101 of the wasm snapshots; re-run under wasmtime: `-1` → `-1`, `-5` → `-5`, `-12` → `-21`, `-123` → `-231`, `-4567` → `-5674`.
2. **BEAM field-access failure label is the fall-through label.** The shape is `{test, is_map, {f, N}, …}` / `{get_map_elements, {f, N}, …}` / `{label, N}.` A missing key or a non-map receiver silently yields the receiver instead of `badmap`/`badkey`. Verified: `first(#{y=>4})` returns `#{y => 4}`. This is why `.len` prints `<<"hello">>` / `[1,2,3]` in beam. **Re-check:** confirmed — `first(#{y=>4})` still returns `#{y => 4}` at HEAD (exported and called through `erl`).
3. **BEAM operand staging clobbers x0.** It shows up in binary ops, tuple/list/record literals and call args: `tuple_construct_then_destructure`, `string_compare_via_byte_loop`, `string_concat_*`, `string_equality_*`, `narrow_else_if_chain_*`, `list_literal_of_records_len`. **Re-check:** confirmed — reproduced on every listed slug (beam `both(false,false)`-style clobbers, `badarith [<<"there">>,<<"there">>]`, tuple `40`).
4. **BEAM null representation is inconsistent.** The `null` literal lowers to `{atom, nil}` (`optional_local_equals_null`: `{move, {atom, nil}, {x, 0}}.`), while `?.` guards compare against `{atom, undefined}` (`optional_chaining_on_record_null_returns_zero`: `{test, is_eq, {f, 4}, [{x, 0}, {atom, undefined}]}.`). erl uses `undefined` for both. **Re-check: corrected** — the two lowerings are still there (`beam_asm.zig:1725-1727` for `{atom, nil}`; `:3284`, `:3301`, `:4011` for the `undefined` tests), but the reason it "works" is not item 2: the `?.` lowering has its own non-map/`undefined` fail label (`beam_asm.zig:4011-4023`) that yields `{atom, undefined}` rather than the receiver. Verified: beam `pick(nil)` returns `undefined`, exactly like `pick(undefined)`. A plain (non-`?.`) field read on `nil` still falls through and returns the receiver (item 2).
5. **WAT `?i32` carrier:** `null` is `i32.const 0`, so a present `0` is indistinguishable from null (`optional_local_equals_null`: `i32.const 0` / `local.set $x` / … / `i32.eq`). **Re-check:** confirmed — the snapshot still shows that shape and wasmtime prints `1`.
