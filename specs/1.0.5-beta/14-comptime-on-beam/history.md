Checked before proposing anything, as the front rules require. Sources: `botopink-lang`'s git
history (the spec files were deleted when the specs were restructured into waves on 2026-06-30,
`dc603be` / `c926850`; read them with `git show <sha>`), the delivered `specs/1.0.0-beta/` in the

## Why AtomVM in-process was rejected

Verbatim from `specs/1.0.0-beta/persistent-erl-runtime.md` (in history):

| Blocker | AtomVM | Persistent erl |
|---|---|---|
| `io:format` / stdlib | needs estdlib bundling (~200 LOC shim) | built-in |
| stdout capture | needs dup/pipe shim in C FFI | `io:format` → stdout → pipe |
| Windows support | no platform layer (`generic_unix` only) | full OTP support |
| descriptor walkers | need NIF registration in C | pure Erlang |
| C FFI surface | ~40 C sources, `extern fn`, opaque pointers | zero |
| build complexity | link C sources + libc + libm + pthreads | zero |
| debug | segfault kills the compiler | stack trace in stderr |

This is the record that closes **option E** in [`options.md`](./options.md#5-option-e--a-beam-vm-that-is-not-erl).
Nothing in the measurements of this front changes any row of it.

## The decision that bears directly on option B

The same spec, Step 2, on the host layer:

> **Important:** do NOT write raw BEAM assembly in Zig. The host layer only manages the subprocess
> lifecycle and communicates via the line protocol. All Erlang/BEAM code is generated by the
> existing `beam_asm.zig` codegen backend (comptime vals) or `erlang.zig` backend
> (templates/decorators).

Read narrowly it constrains `persistent_erl.zig`, not the backend, so it does not by itself forbid
[option B](./options.md#2-option-b--emit-beam-bytecode-from-zig). It is quoted here because option B
is the same instinct in a different file, and because **the measured payoff of B over A is ≈ 0.4 ms
per template declaration** — not a fact that justifies reversing it.

## The intent that was never implemented — and what this front revives

The same spec's own diagram:

```
.bp comptime code → BEAM codegen (beam_asm.zig) → BEAM bytecode
                                                       ↓
                                    ┌──────────┐  stdin: "eval <beam_path>\n"
                                    │   erl    │ ←──────────────────────
                                    │(persist.)│
                                    └──────────┘  stdout: "<json>\n"
```

and Step 3: *"Emits BEAM bytecode directly via `beam_asm.zig` (no `.erl` file needed)"*.

**That is the maintainer's 2026-09-17 request, written down in June 2026 and not delivered.** What
shipped instead is the design in `specs/1.0.0-beta/01-test-green/step-1-decorator-eval.md` (D2,
"Eval pelo codegen real"):

```
FnDecl (decorator/template)
  → ast.Program{ decls = [fn] }
  → erlang.emitComptimeModule(program, .{ host_enums, host_records, exports = main/0, forms })
  → .erl único por avaliação (nome = hash do código) → persistent_erl.evalDetailed → JSON
```

The reason the `.erl` path won is legible in that document even though it is not stated as a
decision: the comptime module needs **host glue** — the capture API, the reply encoder, `main/0`'s
`try`/`catch` — and that glue was built as `erl_ast` forms with an Erlang-source renderer
(`codegen/beam/erl_ast.zig`, `erl_emitter.zig`, delivered as D1/F8 of the same spec). `beam_asm.zig`
lowers botopink AST; it has never had a way to render an `erl_ast` tree
([`evidence.md` E11](./evidence.md#e11--the-beam-backend-has-no-comptime-path)). The `.erl` path was
the one with a renderer.

**So this front is not re-proposing a discarded design. It is finishing an abandoned one, and the
thing that abandoned it — the `erl_ast` → `.S` gap — is still there and is measured here.**

## What has been fixed since, and must not be undone

The persistent `erl` server has been hardened twice; any change to
`comptime/runtime/persistent_erl.zig` inherits these and must keep them
(`specs/1.0.4-beta/09-hygiene/README.md` step 1, delivered):

- the logger's default handler is moved off `standard_io` and `main/0` runs with `standard_error`
  as its group leader, so a printing comptime body cannot desynchronise the frame stream
  (`479f4a0`);
- frames are `latin1` and length-prefixed, with a 16 MiB cap that reports a desynchronised stream
  as a transport error instead of allocating whatever a corrupted prefix says;
- the server is built into `.botopinkbuild/tmp/persistent_erl/<hash>/` through a staging directory
  renamed into place, so concurrent compiler processes in one working directory never read a
  truncated `.beam` (`9732dab`);
- the child's stderr goes to `erl.stderr.log`, never inherited — an orphan holding the parent's
  stderr open wedges `zig build test`.

A new protocol command (options C and A both add one) is an addition to this protocol, not a
replacement of it.
